Open Settings with Ctrl+, or the main menu. It is a page inside the existing window. Changes save automatically; no manual reload is needed. Reset removes a GUI override so the base configuration or built-in default applies again. Reset All Settings removes the browser override set.

Settings stays open when another window gains focus, preserving your selected category and unfinished edits. Close it with Escape or its close button. Settings follows the available window size while open. Enlarging the window restores its normal dialog size; narrowing it switches to compact category navigation without resetting your selected category or edits.

Luciole uses `luciole/` for its application-owned directories. Existing data under the previous application name is not imported automatically. To retain settings or built-in Places layout, move the corresponding files into the paths documented below while the application is closed.

## Files and precedence

Settings load in this order:

1. Built-in defaults.
2. `$XDG_CONFIG_HOME/luciole/config.toml`, your optional base configuration.
3. `$XDG_CONFIG_HOME/luciole/settings.toml`, writable GUI overrides.

When `XDG_CONFIG_HOME` is unset, use `~/.config`. Luciole never writes through your base configuration. This lets Nix or another declarative tool own `config.toml` while GUI changes remain writable in `settings.toml`. A base edit hidden by a GUI override becomes effective after resetting that preference.

Valid external changes apply automatically. Unknown keys in either settings file produce a warning and are ignored, so obsolete settings do not prevent startup or reload. Recognized preferences still apply. GUI saves and Reset preserve unknown keys and their values; they never rewrite your base file. Unknown options do not enable unsupported features. Incorrect types, unsupported values, incompatible schema versions and invalid TOML remain errors; invalid reloads keep the last working settings. `luciole config validate <file>` remains strict and reports unknown keys too. Luciole does not search `/etc/xdg` or a packaged default configuration.

This is a valid starting configuration, not a required file:

```toml
schema_version = 1

[browser]
view_mode = "list"
show_hidden = false
show_preview = true
preview_width = 320
activation_mode = "double_click"
typing_mode = "search"
drop_action = "menu"
switch_to_new_tab = true
confirm_permanent_deletion = true
restore_last_window = false
single_window = false
compact_menus = true
show_close_buttons = true
background_opacity = 1.0
corner_radius_scale = 1.0
sort_by = "name"
directories_first = true
hidden_last = false
```

Validate one file without opening a window or reading adjacent GUI overrides:

```sh
luciole config validate /path/to/config.toml
```

`schema_version` is optional; when present it must be integer `1`.

## Icon theme

File and folder artwork follows the desktop icon theme. Theme selection changes and edits to active SVG/PNG artwork refresh automatically. If desktop settings support is unavailable, Luciole uses the icon theme named by GTK settings.ini. Nix users need a fresh development shell after updating runtime dependencies.

Icon themes that declare `FollowsColorScheme=true` in their `index.theme` (Breeze, Tela, Colloid, and others) draw their recolorable parts with the `colors.toml` palette, as KDE apps do: folders take the primary color and monochrome icons the text color. They update when the palette changes. Other themes keep their own colors.

### List columns

Name is always present. Type, Size and Modified are visible by default. Accessed, Created, Owner, Group, Permissions and Location are optional and hidden by default.

Visibility keys are `show_type_column`, `show_size_column`, `show_modified_column`, `show_accessed_column`, `show_created_column`, `show_owner_column`, `show_group_column`, `show_permissions_column` and `show_location_column`.

`column_order` accepts unique metadata column names. It must include `"type"`, `"size"` and `"modified"`; the optional names are `"accessed"`, `"created"`, `"owner"`, `"group"`, `"permissions"` and `"location"`. Omitted optional columns are appended in their default order. Name is not an entry in this array.

Width keys and defaults:

| Key | Default |
| --- | --- |
| `name_column_width` | `0` (automatic) |
| `type_column_width` | `152` |
| `size_column_width` | `118` |
| `modified_column_width` | `156` |
| `accessed_column_width` | `156` |
| `created_column_width` | `156` |
| `owner_column_width` | `128` |
| `group_column_width` | `128` |
| `permissions_column_width` | `112` |
| `location_column_width` | `260` |

Name accepts `0` for automatic sizing or an integer from `160` through `16384`. Other column widths accept integers from `64` through `2048`.

### Thumbnails

| Key | Default | Accepted values |
| --- | --- | --- |
| `thumbnail_policy` | `"local"` | `"never"`, `"local"`, `"all"` |
| `thumbnail_max_file_mib` | `64` | Image/PDF source limit, integer `1` through `1024`; does not limit video/audio file size |
| `thumbnail_cache_mib` | `1024` | Integer `16` through `8192`; bounds the whole shared cache, oldest thumbnails pruned first |

Local policy generates thumbnails for eligible local files. It skips network shares and FUSE mounts without a local disk, such as rclone and sshfs. A FUSE mount of local files that has no disk of its own, such as gocryptfs, is skipped too; choose All Locations to get its thumbnails. To generate thumbnails on mounted network shares such as `/mnt/media`, choose Settings → Thumbnails → Show Thumbnails → All Locations. All permits generation from filesystem paths, including mounted shares, and reuses the shared thumbnail cache. Locations without a filesystem path remain cache-only; Luciole does not download entire remote files for thumbnail generation.

The Image/PDF Size Limit applies to image and PDF sources. Video stills and embedded audio artwork use seekable media access and are not rejected merely because their files exceed that limit. There is no pixel-count limit: a decoding helper's memory, CPU time and output limits decide how large an image can be, which admits phone photos up to about 200 megapixels. Settings also provides cache inspection/clearing. Luciole reuses compatible shared thumbnails and preserves cache files created or replaced by other applications. Older Luciole video thumbnails regenerate using representative frames instead of always taking the opening frame. With `ffmpegthumbnailer` installed, newly generated video thumbnails include its filmstrip edges, stored in the shared cache so other file managers display them too. Missing/failing helpers keep a plain thumbnail. The edges come from the thumbnailer rather than the icon theme. Native video previews generate clean frames separately.

### Keyboard shortcuts

Shortcuts live in `[browser.keybinds]`. Each key names a command and holds an array of up to four chords. Commands you omit keep their built-in defaults; an empty array unassigns the command. Saving from Settings → Keybinds writes only the commands that differ from the inherited configuration, so restoring a built-in default still overrides a custom `config.toml`. Reset all settings restores every default.

```toml
[browser.keybinds]
search = ["Ctrl+F", "Ctrl+K"]
open_in_new_tab = ["Ctrl+Return"]
zoom_in = ["Ctrl+equal", "Ctrl+plus", "Ctrl+Shift+plus", "Ctrl+KP_Add"]
quick_preview = []
```

Commands are grouped into three independent scopes. Two commands in the same scope cannot share a chord; the same chord can appear once in each scope. The keybinds section refuses same-scope conflicts, and warns when a chord is already used in another scope because the other command may take precedence depending on focus. Super combinations are reserved for the compositor and are rejected. Unlike other settings tables, an unknown command name or malformed chord in `[browser.keybinds]` invalidates the whole file, so check the reported error before restarting.

| Scope | Commands |
| --- | --- |
| Controls | `validate`, `cancel`, `focus_next`, `focus_previous`, `move_left`, `move_right`, `move_up`, `move_down`, `move_first`, `move_last`, `move_page_up`, `move_page_down` |
| File Browser | `back`, `forward`, `up`, `home_folder`, `refresh`, `edit_location`, `search`, `view_grid`, `view_list`, `view_miller`, `toggle_hidden`, `toggle_sidebar`, `toggle_preview`, `quick_preview`, `open`, `open_in_new_tab`, `open_in_new_tab_background`, `toggle_selection`, `rename`, `create_folder`, `create_file`, `cut`, `copy`, `paste`, `trash`, `delete_permanently`, `properties`, `terminal`, `parent_folder`, `context_menu`, `select_all`, `invert_selection`, `select_pattern`, `clear_selection`, `undo`, `redo`, `settings`, `keyboard_shortcuts`, `zoom_in`, `zoom_out`, `zoom_reset` |
| Tabs and Windows | `new_tab`, `close_tab`, `duplicate_tab`, `reopen_tab`, `next_tab`, `previous_tab`, `split_view`, `switch_area`, `close_pane`, `new_window`, `close_window`, `fullscreen`, `quit`, `select_tab_1`, `select_tab_2`, `select_tab_3`, `select_tab_4`, `select_tab_5`, `select_tab_6`, `select_tab_7`, `select_tab_8`, `select_tab_9` |

The archive viewer follows `cancel`, `focus_next`, `focus_previous`, `move_up`, `move_down`, `move_first`, `move_last`, `move_page_up`, `move_page_down`, `select_all`, `parent_folder`, `up` and `open`. `quit` is handled globally, including while an archive or menu popup is open. `select_tab_9` always selects the last tab. Other Escape handlers (returning to the file list, the location bar, search completion, menus, previews and dialogs) also follow `cancel`; `clear_selection` still clears the file list selection.

Chords use key names such as `Return`, `Escape`, `Tab`, `space`, `BackSpace`, `Delete`, `Menu`, `Home`, `End`, `Page_Up`, `Page_Down`, `equal`, `minus`, `plus`, `comma`, `KP_Add`, `KP_0` and function keys such as `F4` and `F5`. `Next`/`Prior` are accepted aliases for `Page_Down`/`Page_Up`. `Ctrl+,` and `Ctrl++` are accepted as shorthands for `Ctrl+comma` and `Ctrl+plus`. Except for `validate` and `quick_preview`, printable keys need Ctrl, Alt or another modifier; Shift alone is not enough. Changes apply to open windows immediately.

## Other writable data

User bookmarks live in `$XDG_CONFIG_HOME/gtk-3.0/bookmarks`, defaulting to `~/.config/gtk-3.0/bookmarks`, shared with Nemo, Nautilus and GTK file choosers. Each line contains a URI and an optional label separated by a space. The older `~/.gtk-bookmarks` is read as a fallback when the modern file has not been found; edits go to the modern path. Read-only or symlink-managed files can be displayed, but Luciole refuses edits that would replace a read-only or linked file. Old Luciole pins are not migrated.

Built-in Places layout, optional last-window tab state and the last file picker folder remain in `$XDG_STATE_HOME/luciole/state.toml`, defaulting to `~/.local/state/luciole/state.toml`. Cached user rows there preserve their placement among built-ins; their contents always come from the shared bookmark file. Deleting a shared user bookmark removes it from Luciole even when an old cache row remains. Tab restoration is controlled by `browser.restore_last_window`.

Per-folder sort and view choices live in `$XDG_STATE_HOME/luciole/folder_views.toml`, one `[[folders]]` row per folder URI with optional `sort_by`, `sort_descending`, `directories_first`, `hidden_last` and `view_mode` (`"list"` or `"grid"`) fields. Invalid rows are skipped. Luciole replaces an unreadable file with its in-memory settings the next time a folder's settings change. It keeps the 4096 most recently changed folders, or fewer when their rows would make the file larger than 240 KiB; the least recently changed go first.

Custom bookmark icons are saved as an optional `icon` field on the matching bookmark row in this private state file. They are Luciole-only; the shared GTK bookmark format has no icon field.

Thumbnails use the shared `$XDG_CACHE_HOME/thumbnails/` cache. The default cache root is `~/.cache`. Custom actions live in the [Scripts directory](/luciole/scripts/).

An optional `colors.toml` beside the settings files supplies the supported Noctalia palette handoff. The installed template is `share/luciole/templates/colors.toml`; UI-scale preferences remain planned. See [Packaging](https://github.com/noctalia-dev/luciole/blob/main/PACKAGING.md#configuration-and-writable-data) for the complete ownership and installation notes.

Text follows the system font: the family and size from GNOME's `font-name` setting, or `gtk-font-name` in `~/.config/gtk-3.0/settings.ini` (then `gtk-4.0`), as written by GNOME Settings or nwg-look. The size sets body text (11 pt is about 14.7 px) and other text keeps its proportions; without a system font, Luciole uses Fontconfig's `sans-serif` at 14 px. GNOME's Large Text (`text-scaling-factor`) multiplies it. Changes apply to open windows right away, including symlinked `settings.ini` files. Icons keep their size.

## Terminal selection

Settings → General → Terminal sets Luciole's terminal command, for example `foot`, `kitty` or `foot --app-id=Luciole`. Press Enter or leave the field to save. This preference applies to Open Terminal Here, Run in Terminal and opening files with terminal-based applications, including Open With and explicitly confirmed terminal application launchers. It does not change another application's terminal preference or the file's associated editor.

Selection order is the configured command, then the process's inherited `TERMINAL` environment variable, then automatic discovery. `TERM` is never an executable preference. Empty `terminal_command` means automatic selection; an explicit missing or malformed command reports an error instead of choosing another terminal. Restart after changing the environment inherited by Luciole; saved preferences apply live across windows.

Automatic discovery tries `xdg-terminal-exec` first, then `x-terminal-emulator` and supported terminal executables. The helper honors shared terminal preferences; without a preference it may choose any eligible installed terminal. Set Luciole's command or `TERMINAL` to choose a particular one when several are installed. With neither helper present, Luciole tries Foot, Kitty, Alacritty, Ghostty, WezTerm, Konsole, GNOME Terminal, Console, Ptyxis, Xfce Terminal and XTerm in that order.

Commands support quoted arguments and `~/` in the executable path, without shell expansion, substitutions or environment assignments. Common terminals get their execution separator automatically. An explicitly supplied trailing `--`, `-e` or `-x` is preserved; custom terminal wrappers can use one of those forms. Automatic executable discovery cannot infer a favorite terminal from the fact that several are installed.

Open Terminal Here and Run in Terminal pass the requested folder both as the process directory and through the supported terminal's directory option. This includes Alacritty, Ghostty, WezTerm, Kitty, Foot, Konsole, GNOME Terminal, Console, Ptyxis, MATE Terminal and Xfce Terminal, plus `xdg-terminal-exec`. WezTerm receives `start` when no subcommand is configured. Ordinary Ghostty launches use a separate process so an existing window cannot override the requested directory or command; an explicitly configured `ghostty +new-window` keeps its reuse behavior. Custom wrappers and `x-terminal-emulator` must forward the inherited directory themselves.

Ghostty loads additional `--config-file` files after command-line settings. When supplying one in the terminal command, leave `working-directory` and `gtk-single-instance` out of that additional file so it does not override Luciole's launch options. The normal Ghostty configuration file can keep its usual defaults.

Terminal-based file handlers start in the files' common native containing folder. A terminal application launcher's explicit desktop `Path` takes precedence; otherwise a confirmed launcher uses the folder from which it was run. Remote or mixed-parent file selections without a common native folder retain the handler's default directory.

The terminal preference applies only when an application asks for a terminal. Graphical or client desktop entries marked `Terminal=false` keep their normal behavior. For example, an Emacs Client entry may reuse an existing Emacs frame, including one running inside a terminal; selecting Kitty here does not override the editor's session policy.
