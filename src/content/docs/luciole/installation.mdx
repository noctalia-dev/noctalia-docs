---
title: Installation and startup
description: Install Luciole from a package or build it from source, and start it.
---

Luciole needs a Wayland session with EGL/OpenGL ES support. Neither the Noctalia shell nor a particular compositor is required.

:::note
Trash and remote folders require GVfs: your distribution's GIO/GVfs services, the backends you need (SFTP/SSH, SMB, WebDAV) and a session D-Bus connection. Without a backend, a remote address can fail with **Operation not supported**.
:::

Prefer a distribution package when one exists. Otherwise [build from source](/luciole/building/). Package maintainers find dependencies and the install layout in [PACKAGING.md](https://github.com/noctalia-dev/luciole/blob/main/PACKAGING.md). To use Luciole for other applications' Open and Save dialogs, see [File picker](/luciole/file-picker/).

## Arch Linux

[`luciole-git`](https://aur.archlinux.org/packages/luciole-git) is available in the AUR and builds the latest development version. Install it with an AUR helper such as `paru` or `yay`:

```sh
paru -S luciole-git
# or
yay -S luciole-git
```

The optional helpers are listed as optional dependencies; see [optional features](#optional-features).

## Fedora

[Terra](https://wiki.fyralabs.com/Terra) provides nightly builds:

```sh
sudo dnf install luciole-nightly
```

Alternatively, the [`lemmy/favorites`](https://copr.fedorainfracloud.org/coprs/lemmy/favorites/) COPR repository provides development builds:

```sh
sudo dnf copr enable lemmy/favorites
sudo dnf install luciole-git
```

For Trash and network locations, install `gvfs` and the backends you need, such as `gvfs-smb`.

## Debian and Ubuntu

The NickH APT repository provides Luciole for Debian-based distributions.

### Install the repository signing key

```sh
wget https://pkg.noctalia.dev/deb/nickh-archive-keyring.deb
sudo dpkg -i nickh-archive-keyring.deb
```

### Add the repository

Choose the source matching your distribution:

```sh
# Debian Trixie
sudo wget -O /etc/apt/sources.list.d/noctalia-trixie.sources \
  https://pkg.noctalia.dev/deb/noctalia-trixie.sources

# Debian Sid
sudo wget -O /etc/apt/sources.list.d/noctalia-unstable.sources \
  https://pkg.noctalia.dev/deb/noctalia-unstable.sources

# Ubuntu 26.04
sudo wget -O /etc/apt/sources.list.d/noctalia-resolute.sources \
  https://pkg.noctalia.dev/deb/noctalia-resolute.sources

# Ubuntu 26.10
sudo wget -O /etc/apt/sources.list.d/noctalia-stonking.sources \
  https://pkg.noctalia.dev/deb/noctalia-stonking.sources
```

### Install Luciole

```sh
sudo apt update
sudo apt install luciole
```

The repository provides `amd64` and `arm64` packages only. For Trash and network locations, install `gvfs` and the backends you need, such as `gvfs-backends`.

## NixOS

The flake provides a package, NixOS, Home Manager and hjem modules, and a pinned development environment for `x86_64-linux` and `aarch64-linux`. Enable the `nix-command` and `flakes` experimental features before using the commands below.

Selecting Luciole as the file picker is a separate, optional step; see [File picker on NixOS](/luciole/file-picker/#file-picker-on-nixos).

### GVfs for Trash and remote folders

On NixOS, Trash and remote folders (`sftp://`, `ssh://`, `smb://`, WebDAV) need GVfs services. The Luciole package alone does not enable them, including with `nix run`, Home Manager or hjem.

Add this to your **NixOS system configuration**:

```nix
services.gvfs.enable = true;
```

This is a [NixOS service option](https://github.com/NixOS/nixpkgs/blob/master/nixos/modules/services/desktops/gvfs.nix), not a Home Manager option. Rebuild, then restart Luciole. If the session does not pick up the new service environment, log out and back in.

### Try Luciole

Run Luciole without adding it to your system configuration:

```sh
nix run github:noctalia-dev/luciole
```

To build the package and keep a local result link:

```sh
nix build github:noctalia-dev/luciole
./result/bin/luciole
```

### Add the flake input

Add Luciole to your existing `flake.nix` inputs:

```nix
{
  inputs.luciole.url = "github:noctalia-dev/luciole";
}
```

The module examples below use `inputs`. Pass it to NixOS modules through `specialArgs` in your existing `nixpkgs.lib.nixosSystem` call:

```nix
specialArgs = { inherit inputs; };
```

For standalone Home Manager, use `extraSpecialArgs` in `home-manager.lib.homeManagerConfiguration`. With Home Manager's NixOS module, use `home-manager.extraSpecialArgs = { inherit inputs; };`.

### NixOS module

Import the module in your system configuration and enable Luciole:

```nix
{ inputs, ... }:
{
  imports = [ inputs.luciole.nixosModules.default ];

  programs.luciole.enable = true;
  services.gvfs.enable = true;
}
```

The module installs the application system-wide but does not enable GVfs; enable it as shown. Optional DNS-SD discovery also needs `services.avahi.enable = true;`.

Rebuild using your configuration's host name:

```sh
sudo nixos-rebuild switch --flake .#your-host
```

To install only the package, put `environment.systemPackages = [ inputs.luciole.packages.${pkgs.stdenv.hostPlatform.system}.default ];` in a module receiving `inputs` and `pkgs`, and enable `services.gvfs.enable = true;` yourself. The module makes that list entry unnecessary.

### Home Manager

With Home Manager already configured, import Luciole's module in your home configuration:

```nix
{ inputs, ... }:
{
  imports = [ inputs.luciole.homeModules.default ];

  programs.luciole = {
    enable = true;
    settings = {
      browser = {
        view_mode = "grid";
        show_hidden = false;
      };
    };
  };
}
```

Apply it with your usual Home Manager switch command, or rebuild NixOS when Home Manager is part of the system configuration. On NixOS, set `services.gvfs.enable = true;` in the system configuration, outside `home-manager.users` or `home.nix`. See [GVfs setup](#gvfs-for-trash-and-remote-folders).

### hjem

With hjem already configured, add Luciole's module to `hjem.extraModules` in your NixOS configuration and enable it for your user:

```nix
{ inputs, ... }:
{
  hjem = {
    extraModules = [ inputs.luciole.hjemModules.default ];
    users.your-user.programs.luciole = {
      enable = true;
      settings.browser.view_mode = "grid";
    };
  };

  services.gvfs.enable = true;
}
```

Replace `your-user` with your username, then rebuild NixOS.

Both home modules accept `settings` as an attribute set, a TOML string or a path to a TOML file, and validate it at build time by default. Omitting `settings` leaves `config.toml` untouched. The declarative base lives in `~/.config/luciole/config.toml`; changes made in Settings stay writable in `settings.toml` and take precedence. Reset a preference in Settings to use its declarative value again. See [configuration.md](/luciole/configuration/#files-and-precedence).

### Binary cache

Pre-built binaries are available on [Cachix](https://app.cachix.org/cache/noctalia). Add the cache to the NixOS configuration to avoid compiling locally:

:::note
To use the binary cache, omit `inputs.nixpkgs.follows` from the Luciole input. Overriding any input changes the derivation hash and causes cache misses.
:::

```nix
{
  nix.settings = {
    extra-substituters = [ "https://noctalia.cachix.org" ];
    extra-trusted-public-keys = [ "noctalia.cachix.org-1:pCOR47nnMEo5thcxNDtzWpOxNFQsBRglJzxWPp3dkU4=" ];
  };
}
```

`main` may include a commit CI has not cached yet. The [`cachix`](https://github.com/noctalia-dev/luciole/tree/cachix) branch always points to the latest cached commit:

```nix
{
  inputs.luciole.url = "github:noctalia-dev/luciole/cachix";
}
```

### Updates and development

Update the pinned input from your configuration directory, then apply your configuration again:

```sh
nix flake update luciole
```

For source development, run `nix develop` from a checkout, then use the [development builds](/luciole/building/#development-builds). [Nix packaging](https://github.com/noctalia-dev/luciole/blob/main/PACKAGING.md#nix-integration) documents the wrapper and runtime integration.

## GNU Guix

The third-party channel [`midnight`](https://codeberg.org/stampede/midnight) provides the `luciole` package in the module `(midnight packages luciole)`. Add it to your channels:

```scheme
(channel
  (name 'midnight)
  (url "https://codeberg.org/stampede/midnight.git")
  (branch "main")
  (introduction
    (make-channel-introduction
      "d97d1568954cfcbf543c9fcdfd5771e2b730ae19"
      (openpgp-fingerprint
        "640A 2C3C E948 22D3 394B 40C3 CAFA EECA 00FF 9B1E"))))
```

Run `guix pull --select=midnight`. The `luciole` package is then available for your configuration or for `guix shell`, which tries it without adding it permanently.

:::caution
Add `gvfs-service-type` to the services of your *system* configuration. Trash and remote folders (`sftp://`, `ssh://`, `smb://`, WebDAV) need it, and the package alone does not enable it.
:::

## Optional features

Missing helpers leave ordinary local browsing available. [PACKAGING.md](https://github.com/noctalia-dev/luciole/blob/main/PACKAGING.md#runtime-integration-and-helpers) lists the full requirements.

| Feature | Needs |
|---|---|
| Image formats | Installed GdkPixbuf image loaders (Glycin loaders when GdkPixbuf is built with Glycin) |
| Video and audio thumbnails and metadata | FFmpeg |
| PDF thumbnails and metadata | Poppler utilities |
| Encrypted 7z archives | A system 7-Zip executable |
| Terminal actions | `xdg-terminal-exec` and a suitable terminal |
| Trash and mounted network locations | GIO/GVfs services |
